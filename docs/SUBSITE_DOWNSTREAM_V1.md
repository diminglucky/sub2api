# 下游子站 V1 设计规格

日期：2026-10-09

## 目标

为 Sub2API 增加下游子站能力。每个子站使用独立域名 `xxx.superai.sbs`，拥有自己的注册、登录、用户中心和只读管理看板；用户、余额、充值、API Key、模型和结算统一由主站控制。V1 试点固定使用 `draw.superai.sbs`，前端页面和子站 API 都使用该域名。

子站管理员可以自定义子站价格，但不能管理模型、上游账号、支付配置或主站 API Key 策略。

## 非目标

- 不复制第二套主站后端或数据库。
- 不允许子站直连主站数据库。
- 不允许子站管理上游账号、模型路由或支付配置。
- V1 不实现自动打款；结算只记录应付台账。
- V1 不允许子站绑定任意外部根域名，仅支持 `xxx.superai.sbs`；试点子站为 `draw.superai.sbs`。

## 架构

主站是唯一控制面，继续负责：

- 用户账号、登录态和权限
- 余额、充值订单、支付回调
- API Key、模型、分组、上游账号池
- 实际转发和计费
- 子站归属、价格覆盖和结算台账

子站前端是独立下游应用，负责：

- 子站品牌、Logo、主题和首页内容
- 注册、登录和用户中心
- 充值入口、余额、用量和订单展示
- 子站管理员看板
- 子站价格和结算明细展示

子站前端只调用主站内部的版本化 API，不依赖主站数据库结构。

## 域名与路由

- 使用通配符域名 `*.superai.sbs`。
- 边缘层根据 Host 识别子域名，例如 `draw.superai.sbs` 对应 `draw`。
- 边缘层只把已注册且启用的子站转发到下游服务。
- 未注册子域名返回 404。
- V1 下游服务只从 Host 读取子站上下文；不从客户端传入的 `X-Downstream-Slug` 等 header 信任子站归属。未来若使用内部 header，必须只允许可信边缘在私有链路上生成并清洗。
- V1 的前端页面和子站 API 都使用同一域名 `draw.superai.sbs`；OpenAI 兼容接口继续使用 `https://draw.superai.sbs/v1/...`，不改变 `/v1` 路径和 OpenAI 请求格式。

## 权限模型

- 主站超级管理员：管理全部子站、价格、结算和用户。
- 子站管理员：只能管理本子站价格、查看本子站用户、充值、用量和结算。
- 普通用户：可在主站和已归属子站登录，余额和用量共享。

所有子站数据查询必须由后端按 `subsite_id` 强制过滤，不能依赖前端隐藏。

## 数据模型

新增表：

- `subsites`：子站 ID、slug、域名、名称、Logo、主题、状态、管理员。
- `subsite_members`：用户与子站归属关系，区分管理员和普通成员，并记录来源。
- `subsite_prices`：子站对模型或分组的价格覆盖。
- `settlement_ledger`：充值订单主站收入、平台成本、子站差额和结算状态。

现有表新增字段：

- `payment_orders.subsite_id`：充值订单归属子站。
- `usage_logs.subsite_id`：调用用量归属子站。
- `api_keys.subsite_id`：API Key 归属子站。

`subsite_id` 为空表示主站数据。旧数据不需要迁移。

## 归属流程

1. 用户通过 `draw.superai.sbs` 注册，自动写入该子站的 `subsite_members`。
2. 用户在主站注册后，也可以正常登录任意子站；但只有已关联子站的数据会在该子站后台聚合。
3. 用户在子站充值，订单写入对应 `subsite_id`。
4. 用户在主站创建 API Key 时，选择或自动继承所属子站。
5. API 请求产生用量时写入同一个 `subsite_id`。
6. 主站统一收款。
7. 主站按订单金额、子站价格和主站成本生成 `settlement_ledger`。

## 价格规则

价格解析顺序：

1. `subsite_prices`
2. 主站分组价格
3. 主站基础价格

子站价格只影响展示和该子站来源用户的结算，不修改上游模型配置。

## 登录态

- 账号体系共享，用户可登录主站和子站。
- 子站会话应为 host-only，不写入父域 `.superai.sbs` 共享 Cookie。
- 登录、刷新和退出通过主站认证 API 完成。
- 密码重置、邮件链接和 OAuth 回调必须校验来源域名。
- 子站管理员权限在服务端判定，不能只靠前端路由限制。

## 内部 API

新增版本化内部 API：

```text
/internal/downstream/v1/...
```

V1 至少包含：

- 解析当前子站配置
- 用户注册、登录、会话刷新
- 当前用户余额、充值、用量、订单
- 子站管理员统计
- 子站价格读写
- 结算台账查询

内部 API 使用稳定合同；下游前端不依赖主站内部表结构。

## 低耦合策略

- 子站前端独立目录，不重写主站前端。
- 子站后端逻辑集中到独立模块。
- 数据库以新增表为主，旧表字段保持可选。
- 路由只增加单独注册文件，不重写现有路由。
- 价格和用量接入使用专用接口钩子，默认走主站原逻辑。
- 所有子站能力用开关控制，关闭时行为与当前主站一致。

预期需要接触的主站共享文件：

- 价格解析
- 用量归属
- 支付订单归属
- 路由和依赖注入
- 数据库迁移

除这些点外，子站功能必须集中在独立模块。

## 并行工作流

1. 主站租户模型与迁移
2. 主站内部 API 与权限隔离
3. 子站前端品牌层、注册登录和用户中心
4. 子站价格、用量归属和结算台账
5. 通配符域名、边缘路由和部署
6. 安全测试、契约测试和试点验收

并行开发前先冻结内部 API 字段和数据模型。涉及共享文件的修改由单一工作流负责，其他工作流只消费接口。

## 验收标准

- `draw.superai.sbs` 能独立展示品牌和注册登录。
- 子站注册用户可在主站和子站登录。
- 用户余额、充值、用量与主站一致。
- 子站管理员只能看到本子站数据。
- 子站价格覆盖正确影响展示、订单和结算。
- 关闭子站开关后，主站行为与当前版本一致。
- 主站合并上游更新时，子站改动集中在独立模块和少量钩子。

## 风险

- 价格解析和结算错误会影响真实收款。
- 登录态隔离不严会导致跨站访问风险。
- 子站前端若复制主站页面，会长期落后于主站体验。
- 通配符域名和边缘路由配置错误会导致子站不可达或错误转发。

## V1 实施顺序

1. 冻结数据模型和内部 API 合同。
2. 实现主站租户表、子站成员、价格和结算表。
3. 实现内部 API 和权限过滤。
4. 实现子站前端骨架、登录和用户中心。
5. 接入充值、用量和结算展示。
6. 配置 `*.superai.sbs` 路由和试点子站。
7. 完成安全和结算测试。
